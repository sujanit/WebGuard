This diagram represents the actual communication flow in your project.

Architecture Explanation

The Python scanner sends HTTP requests to the authorized local Juice Shop target. Flask serves the WebGuard dashboard and APIs. MongoDB Atlas stores scan history and findings through PyMongo.

These are two related communication flows: scanner-to-target and dashboard-to-database. The browser does not directly connect to MongoDB.

4. TCP/IP Concepts Used in WebGuard

Application Layer

HTTP requests, HTTP responses and application-level communication.

Transport Layer

TCP provides transport for HTTP and HTTPS connections.

Internet Layer

IP addressing identifies the local loopback destination 127.0.0.1.

Network Access Layer

Handles the underlying local network transmission.

Important Networking Detail

HTTP uses TCP in the configurations used by this project. HTTPS uses TLS over TCP. The exact transport depends on the connection being made.

5. Ports Used in WebGuard

Port / Address Component Purpose
127.0.0.1:3000 Juice Shop Local web application target
127.0.0.1:5000 Flask WebGuard dashboard and API server
MongoDB Atlas endpoint MongoDB Remote database connection through PyMongo

What is a Port?

A port identifies a service or application endpoint on a host. WebGuard uses different local ports for Flask and Juice Shop. MongoDB Atlas uses its configured connection endpoint and port.
